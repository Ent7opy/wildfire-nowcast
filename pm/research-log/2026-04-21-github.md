## Top unmet feature requests (patterns across repos)

1. **Geography breakout — tools are CONUS- or single-country-locked.** simfire #36 "Create map outside of US" and #15 pixel-size tied to LANDFIRE; elmfire #87 "can't run ignitions east of -106 longitude." Global coverage is the single most recurring blocker.
2. **Onboarding / reproducibility friction dominates.** pyro-platform #186: volunteer CS student blocked for two weeks trying to run the stack locally; maintainer rewrites dev section mid-thread. Orion-AI-Lab #1 closed only when users self-patched Torch/Lightning deps.
3. **Data freshness / lineage in FIRMS pipelines is fragile.** datadesk/nasa-wildfires #24, #15, #39 — "FIRMS endpoint moved / SSL / data stopped updating." Maintainer added round-robin + auto-retry. Consumers want a stable, deduplicated, drift-monitored feed.
4. **Historical weather + manual-input fire-behavior knobs.** WorldWindEarth/wildfire #53 "use historical weather," #54 "manual weather inputs," #55 "override fuel models." Operators want scenario / what-if overlays, not just live forecasts.
5. **CSV export + notification plumbing missing in most tools.** pyro-api #521 "export alerts as CSV," #513 "link to platform in notification," #510 detection timestamps. The "tool → ops → records" pipe is consistently underbuilt across OSS.
6. **Spotting / ember physics is a known weakness.** elmfire #111 surfaced an actual `USE_STOCHASTIC_SPOTTING` bug (inputs silently overwritten). Anyone claiming "spread forecast" needs to be honest about spotting limits.
7. **Perimeter generation from VIIRS/MODIS is still hand-rolled per project.** feds-benchmarking, Dixie-Fire-perimeter-interpolation, HighResFirePerimeter all reinvent the same interpolation — no de-facto library.
8. **Operator-UI basics** — bbox alignment, audio alarms, role-based ack — missing because FOSS is research-led (pyro-platform #181, #174, #197).

## Tech stack patterns

- **Python dominates** (FIRMS clients, ML forecasting, orchestrators).
- **Fortran / C++** hold legacy spread-physics (ELMFIRE, ForeFire, FireLib/Behave).
- **R** holds fire-danger statistics (ecmwf/caliver).
- **Julia** essentially absent.
- **Data sources repeat**: NASA FIRMS (MODIS, VIIRS S-NPP, NOAA-20/21), LANDFIRE, ERA5, GFS, HRRR-Smoke, Sentinel-1/2, Landsat, HPWREN cams.
- **Frameworks**: FastAPI + PostGIS + Dash/React for platforms (pyronear mirrors WFN's choice); Streamlit for GEE apps; Jupyter-as-product for research repos.
- **ML**: xgboost / U-Net / ConvLSTM / FasterRCNN; ONNX for edge inference. Few transformer-based spread models in production FOSS.
- **Simulation / RL**: MITRE's simfire+simharness is the only credible open RL harness; Cell2Fire (via fire2a) the main open cellular-automata.

## White space (expected but missing)

- **No open, global, deduplicated, drift-monitored FIRMS ingest library.** datadesk/nasa-wildfires is the closest, but a thin wrapper; no denoiser, no lineage, no freshness SLA. **This is exactly what WFN already has** — real adjacency.
- **No open, AI-native fire-forecast agent** that takes a natural-language question ("what if this fire reaches Paradise by 4pm?") and composes ingest + spread + weather tool calls with cited provenance. WildfireGPT is RAG Q&A only; nothing agentic with tool use.
- **No open operator triage queue / review UI for noisy detections.** WFN's ReviewQueuePanel is legitimately unusual.
- **No open evidence/export pack** ("snapshot this fire now: detections + perimeter + forecast + sources + caveats, sign it"). Every agency rolls its own PDF script.
- **No open library for industrial-source / false-positive masking** at global scale. WFN's `industrial_coverage.py` has no OSS counterpart.
- **No open champion-challenger / gate-report tooling for fire-spread models.** Everyone publishes a paper and a notebook.

## AI / LLM angle

- **WildfireGPT (project-araia, 17 stars)** — only serious AI-native OSS wildfire project. Retrieval-augmented Q&A over wildfire literature; **not operational, not tool-using, not real-time**. Chatbot-on-top, not AI changing the economics.
- **ndoteddy/ndo-ai-agent-fire-hotspot (0 stars, 2026-04)** — solo project wiring Gemini+Llama+Qwen agents onto FIRMS for SEA. Newish pattern, no adoption.
- Pyronear, simfire, ELMFIRE, ForeFire, bcgov/wps — **zero LLM surface**. Established tools are classical-ML + physics. **The AI-native slot in open wildfire tooling is essentially empty.**
- Implication: if WFN positions around "AI-native analyst for fires" (agent that reconciles FIRMS vs. authority perimeters, explains drift, composes evidence pack on demand), there is no existing FOSS competitor — only internal tools at Technosylva / Watch Duty / ESRI that we can't see.

## Surprises (PM attention)

1. **WFN already has three things nobody else has built open-source:** drift-monitored FIRMS ingest with industrial masking, operator review queue, champion-challenger spread registry. That's the defensible shape — not "another dashboard."
2. **The FIRMS-wrapper consumers (LA Times, pyronear, Pantanal devs) keep reinventing the same plumbing.** A clean, drift-monitored FIRMS library with lineage and freshness SLAs would have a real audience among open-source wildfire devs.
3. **BC Government runs its platform in the open (bcgov/wps).** Plausible partner / customer archetype for an agency-facing pivot.
